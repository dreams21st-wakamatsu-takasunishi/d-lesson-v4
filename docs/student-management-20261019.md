# 生徒・校舎管理の整理（2026-10-19）

## 現場の操作

- 生徒管理の登録先は担当範囲と共通校舎台帳から決定する。新規登録先が1校舎なら選択を省略する。
- 本校（main）は既存・確認用として残し、新規登録先から除外する。既存6件の移動・統合・削除はしない。
- 児童名・生年月日・グループを入力し、「登録内容を確認」。児童番号は空き番号を提案し、あいことばは空欄なら自動作成する。確認を取り消した場合は作成しない。
- 登録後はログインカードを印刷する。設定に失敗した場合は同じ児童を再登録せず、一覧の「ログインを設定」から復旧する。
- 一覧に校舎・グループ・利用状態・ログイン設定・Dサポート連携・使用教材を表示する。「ログイン設定確認済み」はAuthの存在・停止状態・本人用アクセス権を照合した表示で、パスワードを実際に入力して試したという意味ではない。
- 休止・在籍終了は学習記録を保持し、本人の練習保存を停止する。再開は利用中へ戻す。先生の従来の削除操作は休止・再開に変更。管理者の完全削除は詳細操作に残す。
- 通信失敗・競合時は保存成功と表示しない。入力を控え、最新情報を再取得してから再試行する。オフライン自動再送・同じ児童を複数端末で同時練習した際の学習JSON全体の競合解決は未実装。

## 保存・権限

- 校舎の正本はlesson_campuses。全体設定内の旧campusesは互換データとして保持するが、オンライン画面の名称・コード取得には使わない。
- 既存の校舎宣言を正本へ取り込む際は名前・コードが不一致なら中止する。児童の内部ID・Auth・所属・既存本文・学習履歴は変更しない。
- 基本情報はpatch_lesson_studentで対象項目だけ更新。行ロックと変更前の値を照合し、教師の担当範囲を変更前後に検査する。
- 旧い児童画面から保存されても氏名・所属・状態・ログイン設定を巻き戻さない。Auth発行・再発行・転籍の保存も専用のservice_role限定RPCで最新JSONへ必要項目だけ合流する。
- lesson_student_campusesは教室所属の信頼済み対応。児童JSONと現在の本人Authメタデータが一致するものだけ初期化する。Dサポートへの情報共有許可（lesson_support_students）とは別で、教材閲覧のために共有児童を増やさない。
- 校舎台帳を追加してもDサポートの連携許可や児童の共有先は自動追加しない。

## 展開・検証

1. Dサポートのscripts/reconcile-lesson-campus.mjs --rollback-test。変更を全て取り消すトランザクション内で基本情報更新・競合・範囲逸脱・休止・旧画面の上書き防止を確認。
2. 同じスクリプトの--apply。承認済み若松高須西校の校舎単位連携許可と教材10題だけを追加する。児童JSON・Auth・本校教材・既存共有許可が不変であることをトランザクション内で検査する。
3. admin-create-student、support-student-registrationをデプロイし、check-student-management-live.mjs --run-fictional-test。隔離した架空校舎・児童・先生・Authだけで確認し全て削除する。
4. 両フロントを公開。Dレッスンの公開コミットとDサポートの公開版を照合する。

補足: バックアップJSONだけではAuth・校舎教材・共有許可等を丸ごと復元できない。管理端末の操作ログも中央監査の代用にはしない。
