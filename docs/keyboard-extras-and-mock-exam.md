# 片手タイピング・検定模擬試験

## 導線

- ホーム → れんしゅう → キーボード → タッチタイピング → 左手タイピング / 右手タイピング。
- ホーム → れんしゅう → ぶんしょうをうつ → 文章入力れんしゅう / 模擬試験。
- 模擬試験の受検回は、文章課題と同様のカードで選択する。

## 片手タイピング

左右それぞれ5段階を横一列に配置。狭い画面ではステージの領域内だけ横スクロールする。

1. キーボード・ローマ字表示あり、ミス上限なし。
2. キーボード非表示・ローマ字表示あり、ミス上限なし。
3. キーボード・正解ローマ字は非表示。自分が入力したローマ字だけ表示。ミス上限なし。
4. キーボード・正解ローマ字は非表示。自分が入力したローマ字だけ表示。試験はミス5回まで継続し、6回目で終了。
5. 同じ手のかくにんテスト合格後に「90びょうチャレンジ」を開放。キーボード・正解ローマ字は非表示で、入力中のローマ字のみ表示。ミス上限なし。

- 左右100種類ずつ（単語30・短文50・感嘆詞や擬音語20）を登録。1〜4は各回12問を無作為に出題し、チャレンジは90秒間続けて出題する。
- 片手以外のキーを使う別入力も認めない。
- oneHandProgress にクリア回数・最短時間・最終日時を保存。
- 1〜4は初回40コイン、以降5コイン。チャレンジはスコア記録用でコイン付与なし。既存 STAGE_ORDER / keyboardSequence は変更しない。
- ローマ字共通規則は通常練習、テスト、特訓、表入力、ミニゲームにも適用。
- CA/か、CI/し、CU・QU/く、CO/こ、CE/せ、YI/い、WU・WHU/う、CYA系・QA系、XN/ん等は除外。
- SI/SHI、TI/CHI、TU/TSU、HU/FU、ZI/JI等の一般的な別入力は保持。ぢ=DI/JI、づ=DU/ZUも従来通り。

### 90秒チャレンジの記録

- スコアは `max(0, 正しく入力したローマ字数 - ミスタイプ数)`。Backspaceで取り消した文字は正しい入力数から差し引く。長押しの自動リピートは計上しない。
- Spaceで開始した時点から90秒。タブ復帰時も期限を確認し、期限後のキーは採点しない。
- `oneHandChallenges.left/right` に完走回数・最高記録・最新記録を保存する。各記録は点数・正しい文字数・ミス数・正確さ・90秒・終了日時のみで、入力本文は保存しない。
- 同点ではミスが少ない記録を優先。最高記録はステージカードにも表示する。
- 途中終了・ユーザー切替では完走記録を追加しない。ゲストは既存仕様通りクラウドへ保存しない。
- ブラウザ確認: `node scripts/check-one-hand-challenge-ui.mjs --cli <playwright-cliのcli.js>`。実児童データやクラウドへの接続は使わない。

## 公式アプリの組み込み

2026-11-05、ユーザーから過去問本文と公式アプリのHTML / JavaScript / 専用フォントのWeb配信許諾を確認済みとの回答を受領。

- 元フォルダ「文章入力スピード認定試験アプリ」は変更しない。
- public/official-exam に公式配布ファイル53件を複製し、iframe内で使用。
- 公式のHTML構造、CSS、専用フォント、文字編集処理、40文字・36行の用紙、自動改ページ、罫線、登録ダイアログ、2段階リセット、保存確認を使用する。
- Dレッスン側のCSSはiframe内に適用しない。追加するのは操作対象の外枠のみ。
- HTTP実行用にHTMLの file: リソース参照を相対URLに変換。氏名・受験番号はURLフラグメントで渡し、子画面側の履歴をクライアント内だけで更新する。
- 子画面はno-referrerとし、氏名等を静的ファイルのリクエストURL・Refererへ載せない。
- 元アプリの別窓への移動をiframe内の移動に差し替える。
- Dレッスン側で離脱確認後は、子画面の重複したbeforeunload確認を抑止する。
- iframe内の実際のキー・ポインター操作は、既存の自動ログアウトタイマーへ伝達する。定期的な架空操作による延命はしない。
- 元JS・CSS・フォントのSHA-256をsource-manifest.jsonに記録する。
- 再作成: node scripts/prepare-official-exam.mjs [許諾済み公式アプリフォルダ]

音声・補助操作はiframe外のガイド帯に配置し、公式アプリ自体のレイアウトを変更しない。
元アプリはデスクトップ用である。狭い画面でも公式の用紙・ダイアログを縮小改変しない。

## 試験の進行

1. 第78〜85回のカードから選択。
2. ヘッドホンの着用と聞こえ方・音量調整を案内。「音声をためす」で再生し、「聞こえた・次へ」で公式アプリへ進む。
3. 公式初期画面の「受験者登録」を強調。音声で登録を促す。
4. 公式登録ダイアログで受験番号・名前・OKを操作する。
5. 表示内容の確認を促し「入力画面を開く」を強調。
6. 選択した回の紙の問題用紙を教室内のファイルから持ってくるよう案内。開始前・終了時とも「裏面の白紙を上にして」と説明する。「準備できた」をオレンジの枠で強調。指慣らしは行わない。
7. 用意して → 3秒 → 始め。10分間入力。8分経過時に残り2分を案内。
8. 終了時に入力をロック。「やめ〜結果を表示します。」の音声終了後、参考採点・ミス表示へ進む。保存操作は必須にしない。
9. 結果画面の「結果を保存」は任意。模擬試験と明記したファイルを保存できる。

音声はブラウザの日本語音声合成を使用。音声オフ・再読み上げに対応する。
案内文は23px（狭い画面では21px）とし、漢字にrubyで読み仮名を付ける。読み上げにはrubyの親文字だけを渡し、読み仮名を二重に読ませない。
終了音声を再生し直した場合は、再生し直した音声の終了を待つ。音声オフ・再生エラー・60秒の無応答時は待機を解除し、利用不能な音声で進行が止まらないようにする。画面離脱後の古い音声イベントで結果を開かない。
試験中は操作枠を外し、入力に集中できるようにする。
タイマーは開始時点の期限で判定し、タブのタイマー間引きで延長しない。
終了後のIME未確定文字は解答に含めず、画面移動後の処理で別ユーザーの記録を作らない。
コピー・貼り付け等の制限は公式アプリの処理を維持する。

## 採点・保存

- 添付された日本語採点規則に基づく参考採点であり、正式な認定や合否ではない。
- 純字数=max(0,総字数−ミス数)。公式アプリと紙面累計に合わせ、段落先頭の全角空白と段落改行も総字数に含める。最終段落の後には改行を補わない。
- 公式アプリのTab入力（専用フォントの全角空白5個）を論理的な全角空白1個として扱う。
- 誤字・脱字・転倒・余分な文字・段落・不要改行・連続空白を照合。
- 半角使用は全体で1ミス、読点混在は全体で1ミス。長音・ハイフン、統一された読点の許容を反映。
- 採点は入力済み範囲を照合する。「問題全文を表示する」のチェックでは末尾の未入力部分まで表示するが、純字数・見込み級・保存記録・コインは変えない。
- 完全入力後の2度打ちは総字数から除外。誤りを含む反復や曖昧な対応箇所は職員の確認が必要。
- 入力中の元アプリの保存ボタンは残すが、終了後の保存確認は行わない。任意のダウンロード先はDレッスンの模擬結果ファイルに差し替える。公式提出ファイルは生成しない。
- mockExamRecordsは直近50件の数値・問題ID等のみ。解答本文、登録した受験番号・名前をクラウドへ送らない。
- 端末へ保存した解答ファイルには名前等が含まれる。施設の保管手順に従う。

## 模擬試験のコイン

文章入力練習の既存報酬額を共通関数へ移し、模擬試験は見込み級に対応する額の1.5倍を付与する。文章入力練習の従来の字数境界・金額は変更しない。模擬試験の境界は認定基準（50文字で6級等）と一致させる。

| 見込み級 | コイン |
|---|---:|
| 特級 | 22,500 |
| 初段 | 15,000 |
| 1級 | 12,750 |
| 準1級 | 7,500 |
| 2級 | 3,750 |
| 準2級 | 1,500 |
| 3級 | 750 |
| 4級 | 150 |
| 5級 | 75 |
| 6級 | 45 |
| 6級未満（純字数1以上） | 30 |
| 純字数0 | 0 |

- 途中終了も終了時点の純字数で計算し、途中終了である旨を結果・記録へ残す。
- 同じ試験結果では終了処理を1回だけ実行し、残高・mockExamRecordsのcoins・取り組み記録へ同額を反映する。
- 問題全文の表示切替、再描画、任意ダウンロードでは再付与しない。
- 先生の確認中など既存の保存権限がない場合は、記録・コインとも更新しない。
